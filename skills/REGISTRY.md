## By engineering activity

### Requirements

- [Business Rule Analyst](business-rule-analyst/SKILL.md) (intermediate): Extracts and verifies business rules from requirements, code, data and tests, and flags rules that are implicit, contradictory or undocumented.
- [Edge Case Hunter](edge-case-hunter/SKILL.md) (intermediate): Systematically discovers edge cases, boundary conditions, failure modes and negative scenarios for a requirement or function before implementation, and records them as a scenario matrix.
- [Requirement Analyst](requirement-analyst/SKILL.md) (beginner): Analyses a requirement, user story or ticket before any code is written.

### Planning and exploration

- [Implementation Planner](implementation-planner/SKILL.md) (intermediate): Produces a small-step, test-first implementation plan for a change, grounded in repository evidence and a scenario matrix.
- [Repository Explorer](repository-explorer/SKILL.md) (beginner): Builds an evidence-based map of an unfamiliar codebase: structure, entry points, conventions, tests and the code paths relevant to a task.

### Testing

- [Integration Test Engineer](integration-test-engineer/SKILL.md) (intermediate): Designs and writes integration tests that exercise real boundaries such as database queries, HTTP clients and message handlers, including failure and timeout behaviour.
- [Mutation Testing Specialist](mutation-testing-specialist/SKILL.md) (advanced): Uses mutation testing results, or manual mutation reasoning, to find weak or missing assertions and propose tests that kill surviving mutants.
- [TDD Engineer](tdd-engineer/SKILL.md) (intermediate): Drives implementation through Red, Green, Refactor cycles: writes one failing test from a scenario, makes it pass with the simplest change, then refactors, reporting actual test results at every step.
- [Unit Test Engineer](unit-test-engineer/SKILL.md) (beginner): Designs and writes fast, deterministic unit tests that assert behaviour, cover boundaries and negative cases, and fail when the code is wrong.

### Code quality and correctness

- [Code Quality Reviewer](code-quality-reviewer/SKILL.md) (intermediate): Reviews code for maintainability: clarity, cohesion, coupling, complexity, duplication, naming, SOLID violations and testability, citing concrete locations and proposing proportionate improvements.
- [Control Flow Analyst](control-flow-analyst/SKILL.md) (intermediate): Analyses branching logic for missing branches, unreachable code, contradictory conditions, boolean precedence errors, fall-through and off-by-one comparisons by enumerating the condition space.
- [Defensive Programming Reviewer](defensive-programming-reviewer/SKILL.md) (intermediate): Reviews code for unhandled null, empty, invalid, boundary and failure cases, and recommends intentional behaviour for each (reject, default, retry, escalate) with tests.
- [Refactoring Specialist](refactoring-specialist/SKILL.md) (intermediate): Plans and performs behaviour-preserving refactoring in small, test-protected steps, starting with characterisation tests for untested code.

### Security

- [Security Reviewer](security-reviewer/SKILL.md) (intermediate): Use when reviewing code or a design for security defects: injection, broken authentication and authorisation, secrets, unsafe deserialisation, sensitive data exposure, dependency risk and prompt injection.

### Performance

- [Performance Analyst](performance-analyst/SKILL.md) (advanced): Analyses performance problems with a measure-first approach: defines the metric, finds the bottleneck from profiles, queries or traces, proposes targeted changes and verifies the improvement.

### Debugging and regression

- [Debugging Specialist](debugging-specialist/SKILL.md) (intermediate): Diagnoses defects with a hypothesis-driven method: reproduce, isolate, form falsifiable hypotheses, test them with evidence, fix the root cause with a failing test first.
- [Regression Analyst](regression-analyst/SKILL.md) (intermediate): Assesses the regression risk of a change: identifies impacted behaviour, callers and data, selects or creates regression tests, and checks that existing tests were preserved.

### Architecture and design

- [API Contract Reviewer](api-contract-reviewer/SKILL.md) (intermediate): Reviews API and event contracts for correctness, consistency, backward compatibility, error semantics, versioning and testability.
- [Architecture Reviewer](architecture-reviewer/SKILL.md) (advanced): Reviews designs and architectural changes against quality attributes: modularity, coupling, resilience, scalability, security, operability and cost, and records decisions as ADRs.
- [Database Design Reviewer](database-design-reviewer/SKILL.md) (advanced): Reviews schemas, queries and migrations for integrity, normalisation, indexing, transactional correctness, backwards-compatible rollout and rollback.

### Review and pull requests

- [PR Readiness Reviewer](pr-readiness-reviewer/SKILL.md) (beginner): Checks whether a pull request is ready for human review: scope, tests and their evidence, description, risks, documentation and quality gates.

### Documentation

- [Documentation Engineer](documentation-engineer/SKILL.md) (beginner): Writes and updates accurate documentation from the code and decisions: README, how-to guides, API documentation, runbooks, ADRs and release notes, verified against the code.

## Recommended starting set

If you adopt only a few skills, start with these. They cover the failure modes that cause most AI assisted defects.

1. [Requirement Analyst](requirement-analyst/SKILL.md): Analyses a requirement, user story or ticket before any code is written.
1. [Edge Case Hunter](edge-case-hunter/SKILL.md): Systematically discovers edge cases, boundary conditions, failure modes and negative scenarios for a requirement or function before implementation, and records them as a scenario matrix.
1. [TDD Engineer](tdd-engineer/SKILL.md): Drives implementation through Red, Green, Refactor cycles: writes one failing test from a scenario, makes it pass with the simplest change, then refactors, reporting actual test results at every step.
1. [Defensive Programming Reviewer](defensive-programming-reviewer/SKILL.md): Reviews code for unhandled null, empty, invalid, boundary and failure cases, and recommends intentional behaviour for each (reject, default, retry, escalate) with tests.
1. [PR Readiness Reviewer](pr-readiness-reviewer/SKILL.md): Checks whether a pull request is ready for human review: scope, tests and their evidence, description, risks, documentation and quality gates.
