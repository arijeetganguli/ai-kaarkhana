## 4. Master prompt for GitHub Copilot

This is the prompt I would use in GitHub Copilot Agent mode, opened at the root of a new repository.

It instructs Copilot to build the repository as a complete open source product, rather than simply generating an outline or a few Markdown files.

# Project: AI Kaarkhana

## Mission

Build a production quality, open source AI Engineering Handbook and Developer Operating System.

Repository name: AI Kaarkhana

Tagline: Think like an engineer. Build with AI. Own the outcome.

Repository description:

An open source engineering playbook for AI assisted software development. Practical engineering guidelines, reusable AI skills, prompt libraries, TDD workflows, testing strategies, architecture patterns, code quality standards and developer operating practices.

The repository should become a go to resource for software engineers, technical leads, architects, QA engineers and engineering managers who want to adopt AI assisted development without compromising software quality.

This is not a generic AI introduction, prompt collection or marketing website. It must be a practical, technically credible engineering handbook with reusable assets that developers can use in real software projects.

## 1. Core objectives

Build the repository around these principles:

1. AI is an engineering partner, not a replacement for engineering judgement.
2. Developers remain accountable for all generated code.
3. Requirements must be understood before implementation.
4. AI should identify ambiguity and missing business rules rather than silently inventing them.
5. Test Driven Development should be a preferred implementation approach.
6. Edge cases must be identified before implementation.
7. Generated code must be independently validated.
8. Every important execution path must have intentional behaviour.
9. Static analysis, automated testing and security checks must complement AI reviews.
10. Code quality and production reliability must not be sacrificed for development speed.
11. AI skills should be reusable across different coding assistants.
12. Every guideline should have practical examples, instructions and ready to use prompts.

Create the following top level directories:

- handbook/
- skills/

Create the prompt gallery.

Create end to end workflows and practical code examples.

Phase 6:\

Do not simply create placeholder content to satisfy the folder structure.

Prioritise quality, technical accuracy and practical usability over the number of files.

When information is missing, document assumptions and flag decisions requiring confirmation.

### One additional recommendation

Do not let GitHub Copilot generate the entire repository in one uninterrupted pass. Use the master prompt, but have it execute one phase at a time and validate each phase before moving on. Otherwise, you risk getting 100 Markdown files with repetitive, shallow content.

I would also keep the canonical skills tool agnostic and generate the Copilot specific files from them where appropriate. This avoids maintaining multiple inconsistent versions of the same skill.
